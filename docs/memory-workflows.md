# 记忆与工作流

## 预设、会话与用户身份

- 长期记忆、用户画像和 Dream 任务按 `presetId` 隔离；召回快照按 `presetId + conversationId` 隔离。
- ChatLuna 使用原始预设 ID；Character 通过 `toCharacterMemoryPresetId()` 生成预设 ID。
- `speakerKey` 由平台与用户 ID 生成。昵称变化时，沿用原键，更新预设用户记录及已有画像的 `speakerLabel`，新旧昵称去重保存到 `speakerAliases`。
- 为记忆新增用户关联时，在同一预设级队列内补齐 `living_memory_preset_speaker`，再写入记忆。
- 当前对话者通过 `reconcilePresetSpeaker()` 登记身份、昵称和别名；该操作使用仓库事务。
- 模型提交 `speakerLabels`，服务端按输入材料中的昵称映射解析为 `speakerKeys`。

## 对话接入与消息日志

- ChatLuna 在 `before-chat` 注入当前会话最近一次快照和用户画像；在 `after-chat` 追加实际回复并触发提取。
- Character 经专用生命周期事件维护上下文，通过预设中的 `{living_memory}` 变量注入。
- Character 每次 `message_collect` 开始新一轮。首次求值 `{living_memory}` 时注册会话、补写 session 平台消息并等待回填，从本插件消息池一次读取末条消息及前 `recallHistoryMessages` 条历史，固定为本轮上下文。请求模板与历史模板复用本轮生成的变量文本。
- Character 的 `before-chat` 消费这份上下文并启动异步召回；预设未使用 `{living_memory}` 时，在 `before-chat` 准备同样的上下文。`focusMessage` 继续用于实际回复识别和提取来源描述。
- 会话清空时同步清除快照、召回锚点、提取游标和消息日志，并推进日志纪元。回填只接受当前纪元的消息。
- 消息角色在入账时确定。采集与回填共用同步的消息元素文本化过程，非文本元素转为占位文本；文本化与入账连续执行。
- 说话人与 at 目标使用用户昵称，取 `event.user.name` 或 `resolveUserSpeaker`，缺失时使用 userId。群名片字段为 `author.nick`、`member`、`session.username`。
- 来源消息通过持久化来源关系查询，独立于记忆正文。

## Recall

入口：`src/service/workflows/recall/coordinator.ts`。

- Recall 异步运行，当前对话注入已有快照，新生成快照供后续对话使用。
- `recallIntervalMessages` 为 0 时关闭。会话首次触发立即召回，此后按日志消息数计算间隔，闲聊计入。锚点保存在内存中，重启或召回失败后重新计数，下次触发立即召回。
- ChatLuna 输入历史为当前触发消息之前最近 `recallHistoryMessages` 条日志。Character 当前消息取本轮准备时消息池的末条，历史取其前面最近 `recallHistoryMessages` 条；末条为用户消息时启动召回。
- `subModel` 通过内部 `living_memory_search` 检索活跃记忆，快照保存模型整理后的文本与搜索轨迹。
- 重排序失败时使用混合检索排序。用户关联信息用于说明归属。
- 无可靠结果（包括 `<NO_MEMORY>`）时保留已有快照。
- 召回历史加载失败进入任务失败处理；召回失败记录任务和诊断；`subModel` 未配置时跳过入队，只记录配置诊断。
- 工具参数错误达到上限时终止召回。

## Extraction

入口：`src/service/workflows/extraction/coordinator.ts`。

- 按会话日志游标消费，同会话串行，跨会话并行。积压达到 `extractionWindowMessages` 时打包提取，为 0 时关闭。
- 分块以完整交流（触发消息及其回复）为单位；旁听模式下超出预算的超长段可以拆分。
- 冷启动游标从当时日志末尾开始。
- 单块失败后中断本次提取并保留游标；连续失败 3 次后记录失败任务，跳过该块。
- `enableExtractionWhitelist` 按原始平台 ID 匹配，群聊使用 `scope.guildId`，私聊使用 `scope.userId`；未命中时跳过游标初始化和自动提取。
- 模型结果通过结构化校验后写入。结果必须包含 `reason`；`memories` 为空时正常推进游标。
- 日志块转换后具有有效转写消息才进入模型提取；转换结果为空时记录 `empty-transcript` 并推进游标。提取记忆的来源直接由该批消息构造，手工记忆通过创建接口写入。

## 人设卡片

人设卡片读取沿用表字段及默认值。

入口：`src/service/memory/preset_persona.ts`。

- 提取、Dream 和用户画像使用预设人设卡片；Recall 使用独立提示词。
- 卡片取预设 system 部分的未渲染模板，模型选择删除行，保留部分与原文逐字节一致。
- 卡片服务拥有唯一写入权，工作流通过 `resolveOrGenerateCardText()` 读取，按原文哈希懒更新。持久化记录是卡片状态来源。
- 生成后在预设级队列内重读再写入，保留期间保存的手工卡片；预设已清空时丢弃生成结果。
- `source='manual'` 的卡片由手工维护，清空预设时一并删除。
- 对外提供 `resolvePresetPersona` 与 `getPresetPersonaCard` 只读接口；前者在卡片缺失时返回预设原文。

## 用户画像

入口：`src/service/user_profile.ts`。

- 用户画像在 Dream 内生成，生成与注入受 `enableUserProfileInjection` 控制；用户身份登记独立运行。
- Character 画像选择与本轮召回共用同一份“历史消息＋当前消息”，按其中的用户身份读取已有画像并在本轮变量中注入。例如窗口包含 B、C 的历史发言和 A 的当前发言时，本轮同时注入三人已有的画像；窗口固定后到达的新消息参与后续轮次。
- 结果为 `update` 或 `keep`，均需填写理由。首次生成必须返回 `update`。
- `keep` 保留正文并记录本次输入；输入未变时，下次 Dream 跳过该用户。
- Dream 跳过批次后继续画像阶段；致命中断或取消后停止后续生成和写入。画像失败保留已有画像。
- WebUI 手工编辑的画像参与后续 Dream 更新。

## 记忆写入与查询

- 字段归一化按内部类型契约执行：文本去空白、关键词去重并限量、重要性限制在 0–1，可选字段沿用约定的默认值。模型输出由工具 schema 校验。
- 导入入口解析来源结构，普通记忆读取直接使用已存来源。

- `living_memory_entry.speakerKeys` 保存用户关联，`living_memory_entry_speaker` 索引活跃记忆。状态或关联用户变化时，在同一事务内重写关联行。
- 更新、合并和拆分按提交内容完整填写可变字段与关联用户；各工具的 Dream 处理规则见 [Dream 流程](dream.md)。
- 更新结果复用归一化后的落库记录，checked 读取活跃状态并登记本次 Dream 进度。拆分结果在来源归档事务内批量写入；合并与拆分共用新记忆和归档来源的索引同步，已提交的新 ID 随同步警告返回。
- 快照注入直接读取持久化的最新快照。
- ChatLuna 与 Character 通过 `hydratePromptSections()` 统一取得快照和用户画像，快照正文渲染由注入模块内部完成。
- 说话人登记及记忆注入中的异常向上层调用入口传播，由宿主处理本轮失败。
- `living_memory_get_messages` 使用会话已提供或检索返回的记忆 ID。
- 管理指令的 text/user 删除匹配活跃记忆并归档，profile 删除目标画像；删除操作使用 60 秒确认窗口。

## 运行日志

- Character 每轮变量首次生成成功后，通过 `debug` 控制的单行“记忆注入”摘要记录预设、会话和快照正文长度；画像注入开启时附加“人物画像”正文长度。长度按实际拼入变量的去首尾空白正文统计，同轮重复求值复用文本与已记录的结果。
- 提取积压低于触发门槛时，启用 `debug` 后通过单行“等待记忆提取”摘要展示预设、会话和“消息提取阈值：当前条数/触发门槛 条”。当前条数按本插件消息日志的提取游标之后新增的消息计算，冷启动时从游标初始化的位置起算。
- 提取结果保存完成后，启用 `debug` 时通过单行“记忆提取完成”摘要统一展示预设、会话和提取记忆数量；提取数量为零时同样记录结果。
- 日志统一经 `LivingMemoryLogger` 输出。运行入口创建上下文 logger，业务事件和模型调用沿用预设、会话等上下文；模型日志按阶段命名，调用摘要展示模型与调用序号。
- 提取输入准备完成后，启用 `debug` 时输出单行“开始记忆提取”摘要，展示预设、会话、本批来源消息数量和输入字符数。提取诊断与异常摘要展示预设和会话；人设卡片摘要展示预设；画像生成沿用 Dream 上下文，处理失败时展示人物名称。
- 提取最终结构化失败、用户画像生成失败和人设卡片生成失败输出普通警告；逐次模型响应与校验详情由 `debug` 控制。
- 召回快照保存成功后输出一条“召回快照已更新”中文日志，展示预设、会话和命中记忆数量，并以 `========召回快照========` 分隔完整快照正文；摘要与正文始终显示。
- 召回搜索工具执行完成后，启用 `debug` 时通过“记忆搜索完成”摘要展示预设、会话和当前检索条件下匹配的记忆条数；零条结果同样记录，有结果时附带完整记忆正文。条数表示检索筛选后的结果。
- 召回保持当前快照时，通过单行“召回结束”摘要展示预设、会话和“沿用当前快照”的结果。

### 日志补充约定

ChatLuna 在注入内容准备成功后记录一条“记忆注入”诊断摘要，显示启用部分的正文长度，人物画像启用时显示“人物画像”。调用协调器前的入队提示由实际召回、提取结果替代。召回与提取的跳过、等待分支采用中文诊断摘要；会话清理成功后记录清理结果。启动迁移、任务恢复及过期归档清理使用中文结果摘要。

搜索无匹配记忆时仍输出“匹配 0 条记忆”。重排序失败时以警告说明沿用混合检索排序，原始异常随日志保留。

### 功能关闭时的入口行为

自动提取窗口或召回间隔设为 0 时，在对应入口静默结束。中间件保留共用消息采集，跳过关闭功能的来源准备、窗口转写、触发判定和运行日志。召回模型配置提示仅在自动召回开启时生成。

Character 只需注入已有快照时，直接读取快照；召回或人物画像开启时才准备本轮消息窗口。画像和召回同时开启时继续共享同一份“历史消息＋当前消息”。自动召回开关独立于已有快照注入。

## 异常边界

- 预设目录读取失败向查询入口传播；Character 未接入时按空目录处理。
- 结构化输出仅纠正模型解析错误、schema 不匹配及明确返回的业务校验结果；内部处理异常直接传播。
- 人物画像提示词构造与存储异常向上层传播；供应商请求失败按单用户失败统计。

手工人设卡片读取当前预设原文失败时，查询直接失败。自动人设卡片生成成功后，保存失败直接使本次调用失败。

### 提取后的自动整理

自动提取成功保存后，把本次新记忆 ID 交给同预设的增量 Dream 队列。索引同步失败返回已保存记录及警告，消息游标正常推进，索引继续走后台对账。每个提取块独立提交任务；整理结果详见 [Dream 流程](dream.md)。
