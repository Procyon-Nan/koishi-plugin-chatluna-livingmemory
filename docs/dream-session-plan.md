# 全量 Dream 会话化设计

更新日期：2026-10-19。会话化改造已完成；本文保留当前执行规则、代码职责和验收边界。历史运行证据见[验收记录](dream-session-acceptance.md)，实施过程以 Git 历史为准。

## 1. 范围

- 仅修改 LivingMemory，复用 ChatLuna 公开模型与 Agent 接口，不修改宿主。
- 手动全量 Dream 检查启动时的全部活跃记忆，包括已固化项；预设活跃记忆不足 30 条时不启动。
- 沿用现有分区、HDBSCAN、全局噪声整理和超大簇切分，每批最多 30 条。
- 任务按预设互斥；不新增断点续跑、持久化会话历史、主题树或聚类算法。
- 旧批次执行器、操作数组协议、专用合并事务、增量 Dream 及自动触发均已移除，不保留兼容或降级路径。
- 增量流程重新设计、`persistence/entries.ts` 拆分不属于本次改造。

## 2. 代码职责

```text
src/service/workflows/dream/
├── coordinator.ts               # 触发门槛、预设互斥、任务启动、取消与排空
├── job_runner.ts                # 任务运行状态、终态与结果落库
├── full.ts                      # 全量目标、模型、人设、聚类、会话和画像衔接
├── session/
│   ├── runner.ts                # 单轮决策、串行工具执行、限次与换批
│   ├── state.ts                 # 目标、可访问与已处理集合、批次与覆盖结果
│   ├── history.ts               # 追加式历史、批次起点、用量与压缩
│   └── tools.ts                 # Dream 的范围校验、固化与成功登记
├── clustering.ts                # 聚类编排和每批 30 条上限
├── partitioning.ts
├── partitioning/                # 分区算法
├── hdbscan/                     # 密度聚类算法
├── worker/                      # Worker 协议、客户端和执行入口
└── types.ts                     # 簇、操作统计与任务结果
```

`DreamCluster` 仅保留 `id` 与 `entries`。聚类来源字符串不再进入会话契约。

公共工具统一由 `src/service/memory/tools/index.ts` 的 `createMemoryTool` 创建，各工具实现与 `tool_runtime.ts` 位于同一目录。工厂无状态，按调用创建实例，不建立可变注册表或共享任务状态。

| 暴露面 | 工具 | 调用方职责 |
| --- | --- | --- |
| 主对话 | 检索、来源查询、创建、更新、合并、归档 | 宿主注册与注销、会话作用域、配置开关；检索包含 ID |
| Recall | 检索 | 会话范围、隐藏检索结果 ID、记录搜索轨迹 |
| Dream | 检索、来源查询、更新、合并、归档、checked | 固定预设、可访问范围、固化和覆盖登记；检索包含 ID |

相关模块边界：

| 位置 | 职责 |
| --- | --- |
| `service/prompts/dream.ts` | 唯一的 Dream 系统提示词、完整批次、进度和压缩提示词 |
| `service/prompts/memory_entries.ts`、`prompt_format.ts` | 记忆字段渲染、动态文本转义和消息格式 |
| `service/prompts/memory_tools.ts` | 公共工具描述和参数 schema |
| `service/app/memory_mutation_service.ts` | 预设写入队列、speaker 注册、固化参数和索引同步 |
| `service/persistence/repository.ts`、`entries.ts` | 既有仓库门面及原子事实写入，不新增表 |
| `service/app/living_memory_service.ts` | 工作流装配；停止时先取消并排空 Dream，再关闭 Worker 和索引 |
| `service/user_profile.ts`、`workflows/structured_output.ts` | 画像生成、结构化结果校验及取消传递 |
| `service/logging/model_calls.ts` | 原始响应回调、模型用量和既有诊断日志 |
| `contracts/memory.ts`、`workflows/job_tracker.ts`、客户端任务展示 | `completed / partial / failed` 的持久化与展示 |

局部类型就近定义。复用已有队列、事务、日志和模型能力，不增加通用 Agent 框架、Provider 注册器、缓存管理服务或审计账本。

## 3. 状态与执行循环

`createDreamSessionState(targetMemoryIds)` 从启动时的活跃记忆 ID 初始化固定目标集合。聚类完成后赋入 `clusters`，不重写目标集合；聚类或模型准备失败时仍能报告原始目标范围。

| 状态 | 所有者与用途 |
| --- | --- |
| `targetMemoryIds` | `state.ts`：固定覆盖目标，只读集合 |
| `availableMemoryIds` | `state.ts`：批次、检索或合并结果已提供的 ID |
| `processedMemoryIds` | `state.ts`：成功处理的 ID，用于覆盖统计与跳过重复发批 |
| 批次列表、当前位置、操作统计与跳过记录 | `state.ts`：推进批次并生成最终结果 |
| 消息历史、当前批次起点、最近有效输入用量 | `history.ts`：维护请求与压缩边界 |
| 本批轮数与连续无效轮数 | `runner.ts`：控制继续或跳过 |

当前待处理项由当前批次减去已处理集合计算。覆盖集合不是修改锁，已经处理且仍活跃的记忆可以再次更新、合并或归档；重复操作不增加目标覆盖数。新合成记忆加入可访问范围，但不自动成为新批次；运行期间提取的新记忆也不扩大原始目标。

执行顺序：

1. 读取活跃记忆，建立目标集合，解析配置模型、人设与 speaker，取得聚类批次。
2. 建立固定系统提示词、固定工具集合和一份会话历史。
3. 取下一批，过滤已处理项；空批次跳过，其余追加完整记忆输入。
4. 请求前依据最近有效供应商输入用量判断是否压缩更早批次。
5. 复用 `createOpenAIAgent` 执行一次决策，按返回顺序串行执行全部工具，再判断本批覆盖。
6. 全部处理则换批；否则追加进度或纠错信息，继续本批或达到限制后跳过。
7. 批次遍历结束后执行既有画像阶段，再汇总任务结果；致命中断不再启动画像阶段。

程序管理循环，不使用宿主 `AgentRunner` 的完整循环或私有状态。模型无需提交批次完成，也不能靠普通回答结束尚有待办的批次。

## 4. 工具与成功语义

| 操作 | 成功后登记覆盖 | 固化 |
| --- | --- | --- |
| checked | 确认的全部 ID | 对应活跃记忆设为已固化，必须说明无需改动的理由 |
| 更新 | 目标 ID | 随更新事实一并固化 |
| 合并 | 全部来源 ID | 原子创建的新记忆设为已固化，并归档全部来源 |
| 归档 | 归档的 ID | 不再作为活跃记忆处理 |
| 检索、来源查询 | 不增加覆盖 | 不修改 |

- 操作 ID 必须已经由会话提供；写入还需满足预设归属和活跃状态约束。
- 合并至少需要两个不同来源 ID，不指定 target。更新与合并完整覆盖可变字段及 `speakerKeys`。
- checked 工具只等待注入的处理函数；Dream 负责整组活跃校验、固化和成功登记。
- 写入沿用应用层预设队列及仓库事务。更新、合并的固化随事实提交，避免后置固化失败导致重复操作。
- 事实已提交但索引同步失败时登记成功并返回警告，沿用后台对账；普通失败不登记成功。跳过批次不回滚已提交操作，也不重置其余记忆的固化状态。
- 成功判断使用类型化的执行结果，不解析模型自然语言或日志。
- 每轮原始 assistant 消息只追加一次，保留工具调用 ID、推理与签名等元数据，并配齐工具结果。解析失败的响应作为转义后的纠错数据追加，不重放损坏的调用。

## 5. 限次、任务状态与取消

内部常量固定为每批最多 60 轮，连续 3 轮无有效操作则跳过剩余项。请求失败、全部工具失败或尚有待办时返回普通回答均计为无效；正常检索或至少一个工具成功会重置连续无效计数，但仍计入 60 轮上限。

跳过时保存剩余 ID 和原因，并告知模型进入下一批。最终遗漏按结束时的覆盖集合计算，后续成功处理的早期遗漏不再计入。操作次数和目标覆盖数分别统计。

| 终态 | 判定 |
| --- | --- |
| `completed` | 无致命中断，且全部目标处理完成 |
| `partial` | 遍历结束，部分目标成功处理，仍有遗漏 |
| `failed` | 没有目标成功处理，或任务因不可继续的故障中断 |

整体中断仍保留成功统计和未完成范围。取消信号在模型调用前后、工具之间及画像生成和写入前检查；停止时排空在途任务，不撤销已经提交的事实。

画像继续受 `enableUserProfileInjection` 控制，保留原有生成、跳过和错误处理。批次跳过不取消画像阶段，画像普通失败不撤销整理成果，取消则停止后续画像请求和写入。

## 6. 完整输入与上下文压缩

批次输入保留 ID、类型、正文、摘要、关键词、情绪、重要性、创建与更新时间、speaker 标签等完整模型可见字段。使用既有字段渲染与 XML 转义，不以搜索摘要替代完整批次。

系统提示词包含角色、人设卡片、事实约束和整理原则，仅使用工具会话协议。字段要求由公共工具 schema 定义，不保留旧操作数组或 target 合并规则。

压缩规则：

- 固定阈值为最近有效决策响应的 `usage_metadata.input_tokens >= 200000`，不是累计消费量。原始响应回调记录用量，parser 失败也不丢失上报。
- 在下一次决策前判断。新增批次与工具结果要等后续响应才反映到供应商计数，因此不能保证发出请求前恰好限制在 200k。
- 缺失、非有限或非正值不覆盖最近有效上报；始终没有有效上报时不触发。不采用本地估算、输出量或额外叠加缓存量。
- 仅压缩当前批次起点之前的历史及已有摘要，保留系统提示词、当前完整批次及本批全部交互。
- 摘要记录整理结论、重要关联、约束、失败情况、待关注事项及必要 ID。通过公开模型接口独立调用，不访问未导出的宿主压缩函数。
- 摘要成功且非空后替换历史，并清除旧用量；摘要请求及保留历史的旧 usage 不成为新的主会话基线。
- 压缩失败或首批达到阈值却没有更早批次可压缩时终止任务，保留已提交成果。

输出预算沿用模型配置的正数 `maxTokens`，未限定时在本任务调用级设为 4096。宿主声明的上下文容量扣除输出预算后必须至少容纳 200k；不通过降低阈值适配容量不足的模型。

主会话及摘要请求仍用宿主计数检查容量，超限即失败，避免静默裁剪当前批次。这不参与压缩阈值判断，也不证明供应商真实容量。请求投影省略 assistant 的 `usage_metadata`，防止宿主沿用旧基线；原始历史与其他消息元数据保持不变。

## 7. 请求参数与缓存

普通轮次及换批均只追加历史；系统提示词、人设、工具内容与顺序在任务内固定。进度、剩余 ID 和错误反馈放在末尾，已发送的旧批次不因记忆更新而重写。

压缩后的历史为“原系统提示词 → 更早批次摘要 → 当前完整批次及交互”，随后继续追加。压缩改变了旧历史前缀，不能承诺维持原有长上下文缓存命中。

`runDreamSession()` 从模型的 `invocationParams()` 读取输出预算与已有 `overrideRequestParams`，不再提供另一层参数覆盖入口。任务 ID 通过公开调用参数 `id` 传给 requester，摘要使用独立的 `:compression` 后缀。不修改共享模型或全局 adapter 配置，不按模型名称猜协议，不向所有 adapter 广播供应商专属参数。

| 请求路径 | 接入与边界 |
| --- | --- |
| OpenAI-compatible | 保持前缀并传递任务 ID；宿主是否发送 `prompt_cache_key` 受 adapter 配置影响，键不等于缓存保证 |
| Gemini | 沿用隐式缓存；常规 builder 不创建或引用显式缓存对象 |
| Claude Messages | 保留模型已经配置的请求覆盖参数；本流程不自动添加 `cache_control` |
| 其他 adapter | 沿用宿主请求与用量映射；具体模型和端点的缓存能力需独立核验 |

缓存启用、前缀复用和用量上报分别判断。相同渠道或任务 ID 都不能保证命中，不承诺固定命中率或费用节省比例。

日志保留供应商实际返回的输入、输出、推理及缓存明细。缺失字段记为“未返回”，不擅自记为 0；不跨协议套用统一命中率公式。部分 adapter 的输入字段不含缓存部分，或聚合后丢失输入用量；200k 仍只比较公开响应的 `input_tokens`，不自行猜测或补算，也不修改 ChatLuna。

## 8. 验收与后续边界

详细运行数据、脚本位置和历史限制保留在[验收记录](dream-session-acceptance.md)，不在本文重复实施批次与运行日志。

已验证的核心行为：

- 固定目标、每批最多 30 条、跨批次处理、已处理活跃记忆再次操作及合并结果继续使用。
- 工具成功才登记覆盖，索引失败保留已提交成果；无效轮、60 轮限制、部分完成与取消收尾。
- 200k 按供应商输入用量触发，压缩保留当前完整批次及交互，压缩后不沿用旧 usage。
- Gemini、OpenAI-compatible、Claude 的本地 HTTP 请求结构、工具往返、签名元数据和普通历史前缀。
- 使用隔离数据副本及配置中的 Gemini 完成全量 Dream；构造长历史完成真实压缩。

本次接口精简已通过 lint、类型检查、45 个文件的 367 项测试及本地协议复验。协议模拟不代表真实缓存命中；真实 OpenAI-compatible、Claude 缓存及压缩后主会话缓存仍未确认。Claude 用量聚合和临时宿主卸载日志问题保留为宿主边界，不在本插件增加补偿实现。

后续维护继续遵守：改动范围内验证，避免重复防御和无实际需求的抽象；分批审查，由用户手动提交。
